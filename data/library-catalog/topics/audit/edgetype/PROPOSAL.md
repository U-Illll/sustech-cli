# PROPOSAL · AUDIT-EDGETYPE — 合成加权图 vs 逐边类型

**任务书**：终审⑦（"NPZ 仅三数组，不能逐边审计共现/同簇/层级的组成"）的方案评估与成本核算
**审计对象**：`lib-catalog-data/topics/edges.csr.npz`（R1 修复后版本，836,406 B / 99,268 边 / 5,187 节点）
**约束**：只读主体；产物写 `topics/audit/edgetype/`；无网络
**日期**：见 `edgetype-audit.json` 的 `generated_at`

---

## 0. 结论（TL;DR）

1. **终审意见成立，但性质需要修正。** 不是"不能审计边型"，而是"**不能从产物本身审计边型**"。
   实测（§2）：仅用 `card_topics.jsonl` 重算，可 **bit-exact 复现** `edges.csr.npz` 的三数组
   （`indptr`/`indices`/`weights` 逐位相等，`max_abs_weight_diff = 0.0`），耗时 **1.5 s**。
   所以边型组成今天就能审计 —— 前提是愿意每次付 1.5 s + 拖上 68 MB 的 `cards.jsonl`。

2. **真正的损失是产物自描述性 = 0。** 仅凭 NPZ（+`nodes.json` 结构）：
   - 完全可判定（3 位全知）：**82,964 条 = 83.58%**
   - 有 1 位不可判定：**15,476 条 = 15.59%**
   - 有 2 位不可判定：**828 条 = 0.83%**
   - → **16,304 条（16.42%）必须重算才能定性**（§1.3）

3. **推荐方案 a：新增 `types` u8 数组**，与 `indices` 行序对齐，bitmask `1=共现 / 2=同簇加成 / 4=层级`。
   成本 **+99,510 B 未压缩（+11.9%）**，或 **+12,309 B 用 `savez_compressed`（+1.47%）**。
   **零消费方破坏** —— 已用生产验收门（`acceptance/topics-p2.sh` [1]-[4]）与生产消费方
   （`topics_report.py`）在**全量真图**上端到端实测（§4.3）。

4. **顺带发现一个真实缺陷（3 数组口径下不可见）**：**9 条层级边因 ①/③ 同键去重平局而丢失**。
   全部 9 条的共现计数 `cnt ≥ 50`（w1 饱和到 1.0），与 ③ 的 w3=1.0 打平，
   去重按"较小原始下标"胜出 → 保留的是 ① 行、丢掉的是带 `tie=1e9` 置顶权的 ③ 行 →
   该边改用 ① 的 assoc 排名竞争 top-20 → 被截断（9/9 全部 `assoc < 保留下界`，§1.5）。
   方案 a 让该缺陷**可见且可修**（§4.4）。

## 1. 现状分析：信息损失量化

### 1.1 产物信息面

| 数组 | dtype | shape | 字节 | 语义 |
|---|---|---|---|---|
| `indptr` | int64 | 5,188 | 41,504 | CSR 行偏移 |
| `indices` | int32 | 99,268 | 397,072 | 列索引（有向） |
| `weights` | float32 | 99,268 | 397,072 | `w = clamp(w1 + w2, ≤1.0)`，③ 为 1.0 |

合计 835,648 B 裸数组 / 836,406 B 文件。**三个数组里没有任何一位记录边型**。
`weights` 是三类公式的**求和后**结果：给出 `w` 无法反解 `w1`、`w2`、`w3` 的组成。
NPZ 内不可恢复的量：`cnt(u,v)`、`cnt_sc(u,v)`、`cls_of[u]`。

### 1.2 边型真值分布（重建得到，S3）

| mask | 组成 | 边数 | 占比 |
|---:|---|---:|---:|
| 1 | ① 共现 | 84,888 | 85.51% |
| 3 | ① + ② 同簇加成 | 9,557 | 9.63% |
| 5 | ① + ③ 层级 | 4,104 | 4.13% |
| 7 | ① + ② + ③ | 719 | 0.72% |
| 0,2,4,6 | —（空/单型 ②/单型 ③） | 0 | 0 |

- **多型边 14,380 条（14.49%）** —— 这些边的权重是**不可分解的合成值**，正是终审所指。
- **孤儿边（mask=0）0 条**；两条不变式实测成立：
  - `③ ⟹ ①`：③ 的投票卡必然把对 (主题, cls2) 并入 ① 的 pair 集（**无一反例**）
  - `② ⟹ ①`：② 只在已有 pair 上加成（**无一反例**）
  - ⟹ **bit0（共现）恒为 1**，任何边都至少带 ①。
- ③ 声明 4,832 条，存活 **4,823 条**（差 9 条，见 §1.5）；② 参与有向边 **10,276 条**。

### 1.3 仅凭 NPZ 的可判定性（S4）

可利用三条**可证明**的推理规则（实测反例数均为 **0**）：

| 规则 | 内容 | 依据 |
|---|---|---|
| **I0** | `bit0 ≡ 1`（共现位恒真） | ③⟹① 且边非①即③ ⟹ 无孤儿边 |
| **I1** | `w < 1.0 ⟹ bit2 = 0` | ③ 的 w3=1.0，去重取 max；含 ③ 的边必为 1.0 |
| **I2** | `cluster(u) ≠ cluster(v) ⟹ bit1 = 0` | ② 是 (u,v) 对级加成，跨簇不可能命中 |

据此 3 位中可判定位数：

| 未知位数 | 边数 | 占比 | 含义 |
|---|---:|---:|---|
| 0 位（全判定） | 82,964 | 83.58% | 可由 NPZ 直接定性为"纯 ①" |
| 1 位 | 15,476 | 15.59% | bit1 未知 11,844 ／ bit2 未知 5,288 |
| 2 位 | 828 | 0.83% | 同簇 **且** (kw→cls) 形状 ∧ w=1.0 |
| **需重算** | **16,304** | **16.42%** | — |

- `bit1` 未知 11,844 条 = 同簇端点对（`w` 中无法分离 w1/w2）
- `bit2` 未知 5,288 条 = (kw→cls) 形状 **且** `w == 1.0`（无法区分 ③ 与 ① 饱和）
  - 若不加 I1 的朴素口径：(kw→cls) 形状共 12,148 条 —— I1 白捡回 6,860 条

### 1.4 `w = 1.0` 的歧义（终审的核心痛点）

| 类别 | 边数 |
|---|---:|
| `w ≥ 0.999999` 总计 | **8,010** |
| ├ 真含 ③ 层级 | 4,823 (60.2%) |
| └ **纯 ① 饱和（cnt ≥ 50）** | **3,187 (39.8%)** |

**近四成的 `w=1.0` 边并不是层级边。** 任何把 `w=1.0` 当作"结构边"的消费方
（例：`export_release.py` 的注释即写 "1.0 = 层级边/饱和共现"）都在这 3,187 条上语义模糊。

### 1.5 新发现缺陷：9 条层级边被去重平局吃掉

`topic_edges.topk_csr` 的去重键是 `(src, dst)`，平局按 `w` 取大、再按**原始下标取小**。
① 行先追加、③ 行后追加，因此当 `w1 + w2` 恰好饱和到 **1.0** 时与 ③ 的 `w3 = 1.0` 打平，
**胜出的是 ① 行**，③ 行被丢弃 —— 连带丢掉 ③ 行携带的 `tie = nfreq × 1e9` 置顶权。
该边于是改用 ① 的 `assoc = cnt/√(freq_u·freq_v)` 竞争 top-20，被截断。

| 153 | 实验 | TP3 | 80 | 1.0000 | 0.0217 | 0.0468 |
| 348 | 方法 | F2 | 131 | 1.0000 | 0.0316 | 0.0337 |
| 391 | 时代 | F2 | 79 | 1.0000 | 0.0249 | 0.0278 |

| 427 | 世纪 | I2 | 83 | 1.0000 | 0.0268 | 0.0423 |

影响面：0.19% 的 ③ 边。**3 数组口径下完全不可见** —— 这正是"合成加权图"吞掉信息的实证。

## 2. 从 `card_topics.jsonl` 能重建多少？

### 2.1 保真门：可 bit-exact 重建（S2）

重建输入：`topics/card_topics.jsonl` + `cards.jsonl`（取 `cls2`）+ `index/clusters.npy`（取卡簇标签）
+ `topics/nodes.json`。重建量：**共现 `cnt(u,v)` 与同簇 `cnt_sc(u,v)` 全部可重算恢复**。

| 检查项 | 结果 |
|---|---|
| `indptr` 逐字节相等 | ✅ |
| `indices` 逐字节相等 | ✅ |
| `weights` 逐位相等（float32） | ✅ `max_abs_weight_diff = 0.0` |

重建计数：188,512 卡 / 1,112,854 原始对 / 60,185 原始同簇对 / **330,426 去重对** / 4,832 ③ 边
（与 `p2-build-report.json` 完全一致）。

**结论：共现部分可 100% 重算恢复，边型可 100% 重算恢复。**

### 2.2 但重建**不自足**（关键约束）

`card_topics.jsonl` 每行仅 `{"mms":"...","topics":[4,2271,37,0]}`（均值 49.9 B/卡）：

- ❌ 不含卡的 **`cls2` 节点 id** → 必须回读 `cards.jsonl`（**68.27 MB**）
- ❌ 不含卡的 **簇标签** → 必须回读 `index/clusters.npy`

即"离线审计"实际依赖链很重。**可选加固**（独立于本提案，成本 +2.68 MB）：
给 `card_topics.jsonl` 每行加 `"c":<cls2 节点 id>` 与 `"l":<簇标签>`，
每卡 49.9 → 63.9 B（**+28.0%**），文件 9.55 → **12.23 MB**，即可脱开 68 MB 的 `cards.jsonl` 重算全部边型。

### 2.3 重建成本（方案 c 的代价）

| 项目 | 实测 |
|---|---|
| 全量重算（读 68 MB cards.jsonl + 188,512 行 JSONL 解析 + 计数 + 截断） | **1.5 s**（S1 1.2 s / S2 1.4 s 累计 / `real 1.504s`） |
| 对比：官方 P2 全程（含覆盖率扫描） | 13.9 s |
| 额外依赖 | `cards.jsonl` 68.27 MB + `clusters.npy` + `nodes.json` |

## 3. 方案设计与四维对比

### 3.1 对比表

| 维度 | **a) 增存 `types` u8** | **b) 分类型 CSR ×3** | **c) 维持现状 + 审计脚本** |
|---|---|---|---|
| **存储成本** | **+99,268 B 裸 / +99,510 B 未压缩 (+11.9%) / +12,309 B 压缩 (+1.47%)** | 数组 12→18 个；估 **2,506,944 B ≈ 25.25 × a** | NPZ **+0 B**；旁挂掩码 99,268 B（等于 a，但在产物之外） |
| **查询性能** | 位测试 `(types & M) == M`，O(deg) 向量化，**与现有 CSR 遍历同阶**，不引新索引 | 单型查询扫描量小；**跨型需 3 次遍历 + 归并**；②⊂① 无法独立成图 | NPZ 内**不可查**；每次 1.5 s 重算，或读旁挂掩码（**存在与产物版本漂移的风险**） |
| **兼容性** | ✅ **零破坏**（新增键；实测见 §4.3） | ❌ **高破坏**：`indptr` 语义一分为三，全部读取方须改写 | ✅ 零破坏 |
| **改动面** | `topic_edges.py` 约 15 行 + 验收 1 条断言 + 导出 1 个文件 | `topic_edges.py` 重构 + **全部 6 个消费方**改写 | 0 行改动；但每轮审计需重跑 P2 或维护旁挂文件 |
| **自描述性** | ✅ 产物自含（下游无需 `card_topics.jsonl`） | ✅ 自含 | ❌ **不自描述**（终审问题原样保留） |
| **缺陷可发现性** | ✅ §1.5 的 9 条丢失可见 | ✅ 可见 | ❌ 不可见 |

### 3.2 方案 b 为何不可取（除成本外的结构性原因）

1. **② 无法独立成图**：②⊂①（`cnt_sc > 0 ⟹ cnt > 0`，实测零反例），
   只存在"带 ② 加成的 ① 边"，不存在"纯 ② 边"。
2. **多型边无处安放**：14,380 条多型边（§1.2）在三份 CSR 里必须重复存储，
   且权重需按图分配（② 的 w2 与 ① 的 w1 相加后才 clamp，拆开后**不再等于原权重**）→ 破坏 `w` 的可复现性。
3. **③ 是单向结构边**，与 ①② 的无向对语义不同构，混在"三份同类 CSR"里表达力反而下降。

### 3.3 方案 c 的真实定位

方案 c **可用**（保真门证明可重算），但代价是**每轮审计 1.5 s + 68 MB 依赖**，
且它是**旁路**：产物 schema 不变 ⟹ 终审提出的"不能逐边审计产物组成"**原样保留**。
适合作为**过渡态**，不宜作为终态。

## 4. 推荐方案 a：规格、迁移路径、消费方影响

### 4.1 数组契约（建议写入 `INTERFACE-PROPOSAL.md` 与 `meta.json`）

```
topics/edges.csr.npz
  indptr   int64   (n+1)      —— 不变
  indices  int32   (nnz)      —— 不变
  weights  float32 (nnz)      —— 不变
  types    uint8   (nnz)      —— 新增；与 indices 行序严格对齐；bitmask：
                                  bit0 (1) = ① 卡级共现
                                  bit1 (2) = ② 同簇加成
                                  bit2 (4) = ③ 层级边（主题→众数 cls2，单向）
```

**合法值域**：实测恒为 `{1, 3, 5, 7}`（bit0 恒置位，§1.2）。
建议验收断言：`dtype == uint8` ∧ `len(types) == nnz` ∧ `types ∈ {1,3,5,7}` ∧ `(types & 1).all()`。
若将来新增边型（如 kNN 语义边），扩展为 bit3 即可，向后兼容。

### 4.2 迁移路径

### 4.4 顺带修复：①/③ 同键去重（修 §1.5 的 9 条丢失）

在 `topk_csr` 的去重段，把"按 `w` 取大、平局取小下标"改为"**类型位按 OR 归并、排序键取 max**"：

```python
uk, inv = np.unique(key, return_inverse=True)
tm_or = np.zeros(len(uk), dtype=np.uint8); np.bitwise_or.at(tm_or, inv, tmask)
tie_max = np.full(len(uk), -np.inf);      np.maximum.at(tie_max, inv, tie)
# 保留行：仍按 (w desc, index asc) 取代表行，但其 tmask / tie 用归并后的值
```

效果：① 行与 ③ 行同键时，代表行仍带 `tie = nfreq×1e9` → ③ 边不再被截断（9/9 修复），
且该边类型正确标为 `mask = 5` 或 `7`（多型），而非被静默降级为纯 ①。
**这是方案 a 之外、但只有方案 a 能让它可验证的一处真实收益。**
